# Read-Only SCM Copilot Design

## Goal

Add a read-only, context-aware AI copilot to Novel SCM. It should help users ask operational questions, find exceptions, generate reports, and create visualizations without manually inspecting several pages.

## Scope

The first release supports both:

- Daily operations questions and exception detection
- Report and visualization generation

The copilot is available to signed-in users and follows the existing role and permission system. It cannot change SCM data.

## User experience

- A Copilot entry point is available in the main navigation.
- The copilot opens in a right-side panel and does not replace the current page.
- Current-page context is included when relevant, including the selected PO, warehouse, filters, and date range.
- Users ask questions in plain language.
- Responses may contain explanations, data tables, exception lists, charts, and downloadable reports.
- Suggested prompts change based on the current page.
- Answers show supporting source records, such as PO numbers, SKUs, warehouses, shipment IDs, or invoice IDs.
- The copilot is strictly read-only. It cannot edit, approve, upload, dispatch, or delete records.

Example request:

> Show delayed POs for Bengaluru this month and create an Excel report.

The response should include the delayed PO list, a useful chart when appropriate, source records, and an export action.

## Architecture and data flow

1. The user submits a question in the Copilot panel.
2. The system checks the user's role and permissions.
3. The request is converted into a safe, structured read-only query.
4. The API retrieves only permitted SCM data.
5. The AI summarizes the verified result and selects an output format.
6. The response includes source records and timestamps.
7. Exports are generated from the verified result, not from unverified AI text.

The AI must not receive unrestricted database access. It uses approved read-only query functions for:

- Purchase orders
- Inventory
- Shipments
- Appointments
- Proofs of delivery
- Invoices
- Audit logs

If a request is unclear, the copilot asks a clarification question. If data is missing, it reports that clearly and does not guess.

## Reports and visualizations

Supported first-release exports:

- PDF
- Excel
- CSV
- Print-ready HTML

Supported visualization types include inventory by warehouse, PO status, delivery performance, shipment volume, and invoice status. Users can filter by date range, warehouse, channel, SKU, and status.

Each report includes its generation time, applied filters, and source record IDs. Empty or incomplete data is clearly marked.

## Safety and auditability

- Database results are checked before they are displayed or exported.
- Existing permission rules apply to answers, charts, and exports.
- Requests for unauthorized data are blocked.
- Copilot requests and generated reports are logged for audit and troubleshooting.
- The system must make clear which values come from SCM data and which text is generated by the AI.

## Explicit non-goals for the first release

- No write actions
- No approvals or workflow changes
- No scheduled reports
- No email delivery
- No saved conversations
- No unrestricted SQL access for the AI

## Success criteria

- Users can answer common operational questions without checking several pages manually.
- Generated reports match SCM data.
- A useful report or visualization can be created in under one minute.
- No user can access data outside their permissions.
- Every result can be traced to source records.
